## 2. Goals & Non-Goals

### 2.1 Goals

- **G1**: スキャンと削除を分離し、`disclean scan` がファイルシステムに一切の書き込みを行わないこと（検証: WS-k）。
- **G2**: 削除操作を 7 日間（既定値、`DISCLEAN_QUARANTINE_TTL_DAYS` で 1〜90 日に変更可）取り消せること（`disclean undo <runID>` で隔離前のパスに完全復元）。
- **G3**: 実行した削除・隔離・復元を 1 件残らず JSONL 監査ログに記録し、`disclean history` で参照できること。
- **G4**: 権限不足（TCC）・対象なし・外部ツール未検出を、成功件数に数えず個別の理由付きで報告すること（サイレント失敗ゼロ）。
- **G5**: 対象マシンの実測環境（Apple M4 / 10 コア / 460GB SSD / ホーム約 300GB）で、Tier A+B 全ルールの初回スキャンを 90 秒以内、キャッシュ有効時を 5 秒以内で完了すること。
- **G6**: Tier A（既定選択）のみの実行で、2026-08-20 時点の対象マシンから 60GB 以上を隔離できること（内訳: 未使用シミュレータ約 55GB、パッケージマネージャキャッシュ約 6GB）。
- **G7**: CLI と GUI が同一のコア (`DiscleanKit`) を共有し、同じルールカタログ・同じ隔離庫・同じ監査ログを読み書きすること。
- **G8**: GUI と LP が単一のデザイン言語 HEAVY CANDY（`docs/design-system.md`）で構築され、その受入基準 D-01〜D-08 を全て満たすこと。容量が数値ではなく高さに比例した塊として表示され、破壊的操作がレバーの引き下ろし（またはキーボードの明示操作）を要求すること。
- **G9**: 配布 LP が GitHub Pages 上の静的ファイルのみで動作し、ビルド工程・外部ホストへの通信（Google Fonts を除く）・訪問者データの収集を持たないこと。
- **G10**: OS の更新でキャッシュの置き場所が変わっても、本体を入れ直さずにルール定義だけを受け取れること（署名付きカタログの自動取得。F-17）。
- **G11**: 自動更新によって、**利用者の承認なしに削除対象が増えないこと**。取得は自動、削除対象を拡大する差分の適用は承認必須。署名検証に失敗した配信物は一切適用しないこと（AT-016）。
- **G12**: 更新機能を無効にしても全機能が動作し、無効時はネットワーク接続が 1 件も発生しないこと（AT-016 AC5, WS-o）。

### 2.2 Non-Goals (Out of Scope)

- **NG1**: リスク階層 C（ゴミ箱 / Xcode Archives / `~/Downloads` / Docker・Colima のボリューム / `~/.ollama` `~/.cache/huggingface` のモデル / iOS デバイスバックアップ）の削除機能。理由: 再取得不能または再取得コストが極端に高く、誤操作の代償が回収量に見合わない。サイズ表示と手動手順の提示のみ行う（F-11）。
- **NG2**: sudo による特権昇格。理由: 事故時の被害をホームディレクトリ配下に限定するため。システム領域は表示のみ（F-11）で、削除は一切行わない。
- **NG3**: 常駐プロセス・launchd による自動定期実行。理由: 無人で削除を行う設計は本ツールの「確認してから消す」原則と衝突する。隔離庫の失効処理は次回起動時と明示実行 (`disclean purge`) のみ（F-06）。
- **NG4**: ディスク全体の可視化（DaisyDisk 相当のツリーマップ）。理由: ルールに紐づかない領域の探索は本ツールの対象外。
- **NG5**: 外部ドライブ・ネットワークボリュームの対象化。理由: 隔離庫は同一ボリューム内の rename を前提とするため。別ボリューム上のパスは `skipped(reason: "cross-volume")` として報告する。
- **NG6**: 削除内容のクラウド送信・テレメトリ・クラッシュレポート送信・利用統計・マシン識別子の生成。理由: 監査ログにはユーザーのファイルパスが含まれるため、ローカルに閉じる。**例外は更新の取得のみ**（F-17 / F-18）: 配信元への HTTPS GET を行うが、送信するのはリクエストそのもの（URL と `disclean/<version> (macOS <ver>; <arch>)` の User-Agent）だけで、スキャン結果・パス・識別子を含めない。この例外は `autoUpdate: false` で完全に無効化できる。
- **NG12**: 本体バイナリ・アプリの自動置換（自己書き換え）。理由: 特権昇格や実行中バイナリの差し替えという新しい失敗面・攻撃面を作らないため。検証済みの成果物を提示するところまでを担当し、インストールは Homebrew か利用者の操作に委ねる（F-18）。
- **NG13**: 更新による削除対象の無承認拡大。理由: 遠隔からの変更が、そのまま「消えるものが増える」に直結する設計を作らない。縮小・中立の変更のみ自動適用する（F-17 の分類表）。
- **NG14**: 更新チェックの常駐化（launchd・定期実行エージェント）。理由: NG3 と同じ。チェックはコマンド実行時に、間隔（既定 24 時間）を過ぎている場合のみ行う。
- **NG7**: macOS 以外のプラットフォーム対応。
- **NG8**: 隔離庫の暗号化・改竄検知。理由: ローカルのファイル権限（0700）以上の保護は本バージョンの脅威モデル外（§8.4）。
- **NG9**: LP でのアクセス解析・Cookie・フォーム・メールアドレス収集。理由: 訪問者データを一切持たない方針（NG6 と同じ理由）。ダウンロード数は GitHub Releases 側の統計で足りる。
- **NG10**: LP からのバイナリ直接配信。理由: 配布元を GitHub Releases と Homebrew tap に一本化し、署名・公証済みの成果物以外が出回る経路を作らない。LP は外部リンクのみを置く。
- **NG11**: LP 上でユーザーのマシンを診断する機能。理由: ブラウザからローカルの容量は読めず、読めるかのような表現は誤解を招く。ヒーローのデモは実測の静的データであることを明示する。

### 2.3 Success Metrics

- **M1**: `disclean scan` 実行前後で、`$DISCLEAN_STATE_DIR/quarantine` 配下のエントリ数が変化しない（WS-k で自動検証）。
- **M2**: `disclean apply` で隔離した全項目が `disclean undo <runID>` により元パスに復元され、復元後の合計バイト数が隔離前と一致する（AT-005）。
- **M3**: 実測環境における初回スキャン所要時間 ≤ 90 秒、キャッシュ有効時 ≤ 5 秒（AT-002 で計測）。
- **M4**: Tier A のみ選択時の隔離合計サイズ ≥ 60GB（2026-08-20 の実測環境における手動確認、§11.1 の Verification ブロック）。
- **M5**: `swiftlint lint --strict` が 0 violations、`swift test` の DiscleanKit カバレッジ ≥ 80%。
- **M6**: LP と GUI に対する axe-core の critical + serious 違反が 0 件（D-01, D-04）。
- **M7**: LP の初回表示が 360px 幅で横スクロールを起こさず（D-07）、外部通信が Google Fonts の 2 ホストのみ（D-08）。
- **M8**: 改竄した manifest（署名不一致 / ハッシュ不一致 / 巻き戻し）を 3 種すべて拒否し、`active` カタログが変化しない（AT-016 AC1・AC2）。
- **M9**: 拡大差分を含むカタログが配信された状態で `disclean scan` を実行しても、新しい削除対象が現れない（AT-016 AC3）。
- **M10**: `DISCLEAN_AUTO_UPDATE=0` のとき、`disclean scan` 実行中の外向き接続が 0 件（AT-016 AC5）。
